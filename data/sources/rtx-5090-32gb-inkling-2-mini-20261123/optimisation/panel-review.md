# Independent panel and measurement review

Reviewed 23 November 2026. Scope: `PLAN.md`, `assess.py`, `assess_greedy.py`, completed run records, and the six final answers in each of `control-a` and `cache-warm-a`. No GPU requests, service changes, runner/core edits, or queue changes were made. Code was executed only in a CPU-only isolated container.

## Verdict

The cache experiment demonstrates a substantial startup-time reduction in the observed warm-cache run. It does **not** yet establish a decode-speed improvement or a general answer-latency improvement. Rejecting the first stochastic cache comparison under the preregistered gates is correct. Proceeding with a separately declared temperature-zero panel is a defensible way to remove answer-length differences from the performance comparison; preserve the stochastic observations rather than replacing them.

The panel is useful as a workload mix and smoke screen. It is **not six verified-correct tasks**. Automatic natural-stop/loop checks missed functional errors in the candidate backup script, a complexity overclaim, and a five-paragraph instruction violation. Those errors cannot be attributed to compiler caching from one sampled answer per configuration.

## Measurement integrity

- The six paired prompt hashes match between `control-a` and `cache-warm-a`. The candidate emitted 1.18–1.76 times as many completion tokens depending on task. Whole-answer latency therefore does not isolate hardware execution speed. For example, TCP completion tokens rose from 2785 to 4897 while decode rate changed from 244.53 to 237.42 tokens/s; response time rose from 11.87 to 21.11 seconds. This is mostly answer-length variation, not evidence of a comparable runtime slowdown.
- Candidate startup was 49.49 seconds versus 126.69 and 126.71 seconds for neighbouring controls. Startup plus warmup was 67.54 seconds versus 146.88 and 152.14 seconds. Report both, including the fact that caches had already been populated; this is restart/startup acceleration, not inference throughput acceleration.
- `assess.py` correctly rejects `cache-warm-a`: answer-latency ratio is 1.299 against `control-a`, and aggregate decode-median ratio is 0.931 against `control-b`. The paired median throughput ratios are different statistics (1.061 and 1.016), and their six-task bootstrap intervals include 1. Do not substitute the more favourable paired statistic for the preregistered aggregate gate after looking at the result.
- The six-task bootstrap resamples task labels, not repeated independent runs. Its interval describes sensitivity to this small workload panel; it is not a robust estimate of run-to-run timing uncertainty. The assessment does not use that interval as a qualification gate, so passing its point-estimate thresholds would not itself demonstrate statistical significance.
- `assess_greedy.py` adds whole-panel output equality to the six small sanity cases and compares each candidate with both neighbouring controls. This is conservative and sensible for claiming observed byte-equivalent behaviour. A failure means **byte equivalence was not demonstrated**; it does not alone prove worse answer quality, especially if the controls also differ from one another. Compare controls with controls before attributing divergent text to a change.
- The strict hash covers reasoning plus final answer, which is stronger than merely comparing final answers. Six matching examples still do not establish universal losslessness. Do not claim model-wide semantic equivalence from this finite test.
- `usage_decode_tps = (completion_tokens - 1) / decode_seconds` uses server usage, whereas the previous registry metric re-tokenized streamed visible/reasoning text. These should retain distinct labels. The first SSE event may contain more than one token and special tokens may be included in usage; the standard subtraction is approximate for short responses. It matters much less for these thousands-token panel answers than for the tiny sanity probes.
- The documented period correction is reasonable: the unquoted exact-string instruction ends in a full stop and permits two plausible readings. Raw flags are preserved, both interpretations are treated consistently, and hash equality remains strict. The final qualification should use a quoted or fenced marker as already planned.
- Aggregated median gates can hide a regression in one workload. If the final report says “no workload regressed,” verify paired per-task ratios separately; the existing gate establishes only its named aggregate metrics.

## Reproduced CPU tests

Isolation: Docker `--runtime runc`, no GPU flags, `--network none`, `--read-only`, 256 MiB memory, 0.5 CPU, 64 PIDs, CPU-time ulimit 20 seconds, all capabilities dropped, no-new-privileges, UID/GID 65534. Only small tmpfs work directories were writable; no host directory was mounted. The already-installed pinned vLLM image supplied Python/Bash/coreutils, but no model/server was launched.

- LRU model-authored tests: control 11/11; candidate 9/9.
- Additional LRU oracle: 4000 deterministic random operations per implementation (seed 7319, capacities 1/2/7/31, keys 0–49, 60% puts, varied falsey/container/scalar values), compared after every operation with an OrderedDict reference. Both passed values, size and membership checks.
- Backup ordinary-path test: nine sequential runs with distinct injected timestamps; both succeeded and left seven archives.
- Valid sibling test: source `/work/.../src`, backup destination `/work/.../src-backups`. Control succeeds; candidate returns exit 1 before producing an archive. Cause: `[[ "$BACKUP_ABS" == "$SOURCE_ABS"* ]]` compares a raw prefix rather than equality or a slash-delimited descendant.
- Newline basename test: source directory named `src\nbreak`, destination `out`, distinct timestamps. Control succeeds through nine runs and leaves seven archives. Candidate fails on the fourth run with `rm: cannot remove 'break_20261123_000003.tar.gz': No such file or directory`. Cause: newline-delimited `find -printf`, `sort`, `cut`, `tail` and `read` split one path into multiple records. Spaces are handled; newlines are not.

The initial sandbox run used a no-exec tmpfs, so the timestamp shim was skipped by PATH lookup; that attempt was not used for the distinct-timestamp retention conclusion. The rerun explicitly enabled execution on the disposable work tmpfs and verified the injected filenames. Both attempts reproduced the candidate sibling/newline defects.

## Qualification recommendation

Continue the preregistered deterministic comparison, but keep claims narrow: cached startup acceleration if repeated gates pass; no throughput gain unless measured independently; no blanket “all six tasks correct.” Final qualification should retain functional Daily tests, tool/vision checks, context retrieval and soak checks. Record the backup failures and paragraph/complexity caveats as semantic observations without treating this tiny stochastic panel as a statistically supported quality regression.
