# RTX 2080 8 GB: Bonsai 2 9B and Nemotron 3.5 Bolt E4B

Owner hardware: NVIDIA GeForce RTX 2080 / TU104 / SM75, 8192 MiB, 165 W limit;
headless card (desktop uses the Intel iGPU). Host: i5-9600K, six cores, 64 GB
DDR4-3200, Linux. Each server used the GPU alone; the existing Strata user
service was stopped for the attempt and restored afterward. Generation and
thinking were uncapped throughout the unmodified upstream lab gates.

The two frozen launch JSON files are the exact container contracts tested.
Images and Hugging Face weights are pinned. Download each launch's listed
files at its full revision into a directory, mount that directory read-only
at `/models`, and start its image with the rendered entrypoint, arguments,
port and shared-memory setting. Use bridge networking and map port 8080 to
localhost. `python3 lab/lab.py render <recipe.json>` prints the full contract.

## Ternary Bonsai 2 9B

This uses the official Q2_0 file already represented in the registry, served
by upstream llama.cpp b11804. It does not use the PrismML fork or PQ2_0/MTP
weights from the owner's older experiments.

```sh
python3 lab/lab.py try \
  prism-ml/Ternary-Bonsai-2-9B-gguf@5b2abb02362efbed46bbe204014b02837778b2c2 \
  --model bonsai-2-9b \
  --engine llama.cpp-bonsai-2-9b-q2-0-32k-rtx2080-b11804 \
  --card rtx-2080-8gb --on endpoint \
  --endpoint http://127.0.0.1:8080 --gpu 'NVIDIA GeForce RTX 2080'
```

Input: 2,556,640,128 bytes, SHA256
`1f884aa56aacd2bbbb2e4b7abaead2b1102b74a9c75a23fc33dab916813a384d`.
The existing registry model release date is 2026-09-23, within its age policy.

## Nemotron 3.5 Bolt E4B

```sh
python3 lab/lab.py try \
  unsloth/NVIDIA-Nemotron-3.5-Bolt-E4B-GGUF@b738967d6da3441a7d1c71fcec15e49e32e16ecd \
  --model nemotron-3.5-bolt-e4b \
  --engine llama.cpp-nemotron-3.5-bolt-e4b-ud-q4-k-xl-dflash-64k-rtx2080 \
  --card rtx-2080-8gb --on endpoint \
  --endpoint http://127.0.0.1:8080 --gpu 'NVIDIA GeForce RTX 2080'
```

The current public revision contains a different UD-Q4_K_XL file from the
owner's earlier October 23 experiments. This submission uses the separately
downloaded public revision, verified before serving:

- Target: 5,060,482,240 bytes, SHA256
  `84ff34f5834b929043f5ae74799e8d562d4056998f6a5923ceb44831e8ad84d6`.
- DFlash: 398,892,256 bytes, SHA256
  `9a63662ae8395b8bfc1a1b00d7a9ef354120f172704bd6ba88d3870cf22d4d03`.

Historical speed and agent-task scores are not evidence for these updated
weights. This submission claims only the new lab gates recorded alongside it.

The first Bolt run with template defaults failed the reasoning gate: it
answered 391 correctly but returned no separate thought. Inspection of the
pinned template shows `enable_thinking | default(false)`. The submitted launch
uses `--reasoning on` and a template generation-prefix override; the lab
is unchanged. Only the final passing attempt is included in this contribution;
diagnostic attempts are retained locally. Thinking is not capped.

Bonsai passed all six gates: 71.3 tok/s decode; 25740 context prompt tokens in 23.6 seconds including generation, correct access code. The lab prefill field is 1091 tok/s (whole-request wall time).

The original NVIDIA template is pinned at model revision
`49843eed8db1f1c616c47af75cfd36e07aec0667` (`tokenizer_config.json`). It
permits direct answers even with thinking enabled; both deprecated template
kwargs and the supported `--reasoning on` alone returned 391 without a thought.
The submitted template adds the native `<|channel>thought` generation prefix
when thinking is enabled. All reasoning text is then generated by the model.
The complete template is bound into the frozen launch config and its acceptance
hash. Immediately after the model-turn generation prefix, the override adds:

```jinja
{%- if enable_thinking -%}
    {{- '<|channel>thought\n' -}}
{%- endif -%}
```

Template override SHA256:
`c6bc28779705e25fb1f2de04f3e74b7e4efcc56a1b138a87b5bed5388b90642f`.

Bolt passed all six gates with the explicit thinking-channel template: 84.6 tok/s decode; 52592 context prompt tokens in 30.2 seconds including generation, correct access code. The lab prefill field is 1741 tok/s (whole-request wall time).
